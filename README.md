# 站点证书分阶段轮换库

企业 VPN 中一个站点用同一张身份证书连接多个邻站。本库在**全程保持双向互信**
的前提下分阶段替换身份证书：先让邻站追加信任候选证书，人工确认后本站再切换
身份，最后清除邻站对旧证书的信任。状态全部保存在内存，候选证书为本地生成的
真实自签名 X.509 证书；设备以进程内对象表示，不涉及真实 IPsec 通信。

## 组成

- `cert_rotation.certs` — 真实自签名 X.509 证书生成（RSA-2048，SHA-256 指纹标识）。
- `cert_rotation.device` — 进程内设备模型：完整配置（本站身份证书 + 针对各邻站的
  信任集合）带站点内递增版本号，设备只原子应用更高版本，应用后返回回执。
- `cert_rotation.library` — 轮换库，四类操作：
  - `start_rotation(site)` 发起轮换，生成候选证书并让邻站追加信任；
  - `confirm(site, candidate)` 人工确认，仅授权本次轮换的指定候选证书；
  - `pending_configs()` 获取已下发但未被回执证实的配置（取出≠应用成功）；
  - `submit_receipt(receipt)` 提交应用回执（乱序、重复、迟到均安全）。
  - `is_complete(site)` 查询轮换是否完成。

## 阶段顺序

1. **分发信任**：各邻站配置追加候选证书指纹（信任只增不减，隧道不断）。
2. **等待确认**：全部邻站回执后等待人工确认；确认只授权指定候选证书。
3. **切换身份**：本站配置切换身份为候选证书（邻站已信任，隧道不断）。
4. **清除旧信任**：各邻站配置只保留候选证书指纹（本站已用新证书，隧道不断）。
5. **完成**：`is_complete(site)` 为真，允许再次发起轮换。

配置投递与回执可能乱序、重复或延迟；库只依据回执判断实际应用情况，
版本号单调递增保证迟到的旧配置、旧回执、旧确认不会让状态倒退。

## 运行测试

```bash
python3 -m pytest tests/ -q
```

测试依据设备实际身份证书与对端实际信任集合独立核对每一次应用后的
隧道双向互信，覆盖乱序/重复投递、迟到旧回执、旧确认等场景。
